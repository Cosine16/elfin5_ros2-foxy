### 证据 13: root↔fit 跨用户 DDS 发现失败(2026-09-19 重测)

**方法**: 用两个自建 rclpy 节点互查对方(`scripts/dds_discovery_probe.py`), 逐个变量做对照。
不在现场环境里测, 而是**换到干净 domain**, 避免残留 `/dev/shm` 段与现场进程干扰。

```bash
# A/B 两个探针, 相隔 3s 启动, 各 spin 12~15s, 打印 get_node_names()
# root 侧: sudo -n bash -c 'source /opt/ros/foxy/setup.bash; export ROS_DOMAIN_ID=..; python3 <probe> Root 15'
# fit  侧:                        source /opt/ros/foxy/setup.bash; export ROS_DOMAIN_ID=..; python3 <probe> Fit 12
```

| # | 组合 | domain | `ROS_LOCALHOST_ONLY` | 其它条件 | 结果 |
|---|---|---|---|---|---|
| 1 | fit + fit | 42 | 1 | — | ✅ 互发现 |
| 2 | fit + fit | 45 | 0 | — | ✅ 互发现 |
| 3 | **root + fit** | 42 | 1 | — | ❌ 各只发现自己 |
| 4 | **root + fit** | 44 | 0 | — | ❌ |
| 5 | **root + fit** | 46 | 0 | 已确认两侧都成功绑定 7400 | ❌ |
| 6 | **root + fit** | 42 | 1 | root 侧 `umask 000`(段变 666) | ❌ |
| 7 | **root + fit** | 43 | 1 | `ip link set lo multicast on` + 组播路由指向 lo | ❌ |
| 8 | fit + fit | **0** | 1 | domain 0 里有 root 参与者在跑 | ❌ |

现场取证(第 8 行的实际形态): 6 个节点 2 root(`ros2_control_node`/`static_transform_publisher`)
+ 4 fit(`move_group`/`rviz2`/`elfin_basic_api`/`_ros2_daemon`), 全部 `ROS_LOCALHOST_ONLY=1`,
`ss -lunp` 显示都绑在 `127.0.0.1:7400` 与 `239.255.0.1:7400` —— 但 fit 侧的
`ros2 node list` / `rqt` 一个节点都看不到。

**机理**: 同机通信默认走 Fast-DDS 共享内存(SHM), SHM 段**跨 uid 打不开**;
`ROS_LOCALHOST_ONLY=1` 又把组播限定在回环, 而本机

```bash
ip -o link show lo
# → 1: lo: <LOOPBACK,UP,LOWER_UP> ...     ⬅ 没有 MULTICAST 标志
ip route get 239.255.0.1
# → multicast 239.255.0.1 dev enx000ec68eca09 src 192.168.137.245   ⬅ 组播根本不走 lo
```

于是**没有任何回退通路**。**硬结论: 实机上所有 ROS 进程必须同一 uid。**

**已排除的因素**(逐项验证, 均非原因): `/dev/shm` 容量(16G 用 2%)、
残留 shm 段属主与权限(`umask 000` 无效)、防火墙(iptables 全 ACCEPT / ufw 未启用)、
端口绑定冲突、`ROS_LOCALHOST_ONLY` 与 `source` 的先后顺序(ament 钩子
`1.ros_localhost_only.sh` 实际不会覆盖已设值)、domain 是否干净。

**推论(操作层)**:

| 节点运行身份 | 调试终端身份 | 能否看到节点 | 备注 |
|---|---|---|---|
| root(全 sudo) | fit | ❌ | 这就是"fit 下 rqt 空白"的原因 |
| root(全 sudo) | root | ✅ | `bash scripts/root_ros.sh rqt` 或 `sudo -E rqt` |
| fit(全 `--no-sudo`) | fit | ✅ | **目标形态**, 需先给 `ros2_control_node` setcap + 放开 rtprio |
| root + fit 混跑 | 任一侧 | ❌ | 两组互不可见, 链路直接断 —— **禁止** |

**复现证据 13(约 1 分钟)**:

```bash
cd ~/ws_ros2/cos_ws
P=scripts/dds_discovery_probe.py

# 1) 同 uid 对照: 两个 fit 节点应当互发现
ROS_DOMAIN_ID=42 ROS_LOCALHOST_ONLY=1 python3 $P FitA 15 &
sleep 3
ROS_DOMAIN_ID=42 ROS_LOCALHOST_ONLY=1 python3 $P FitB 12

# 2) 跨 uid 对照: 应当互不可见
sudo -n bash -c "source /opt/ros/foxy/setup.bash; export ROS_DOMAIN_ID=43 ROS_LOCALHOST_ONLY=1; \
                 python3 $P RootA 15" &
sleep 3
ROS_DOMAIN_ID=43 ROS_LOCALHOST_ONLY=1 python3 $P FitC 12
```

预期: 第 1 组双方各看到 2 个节点; 第 2 组双方各只看到自己 1 个。
若第 2 组也能互发现, 说明本机环境已变(例如默认路由网卡或 `lo` 的组播能力变了), 请更新本条记录。
