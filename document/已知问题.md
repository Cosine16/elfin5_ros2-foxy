## Launch 死代码（误导性，建议修）

### 6. `elfin5_gazebo.launch.py` 不加载控制器
- `elfin5_ros2_gazebo/launch/elfin5_gazebo.launch.py:87-95` 定义了两个 `ros2 control load_start_controller`，但**未加入 LaunchDescription**。单独启动它机械臂无法控制，且死代码里的控制器名 `joint_trajectory_controller` 与实际 `elfin_arm_controller` 不一致。

### 7. 真机两个 launch 各只启动一半
- `elfin5_moveit.launch.py`：构造了 move_group/RViz/spawner 但**只启动** static_tf + RSP + ros2_control_node。
- `elfin5_moveit_rviz.launch.py`：相反，**只启动** move_group + RViz + spawner，RSP/ros2_control_node 是死代码。
- 两者必须配对使用（官方 4 步流程就是这么干的），但单看任一文件都会误判。

### 8. `elfin_basic_api/launch/elfin_basic_api.launch.py` 引用不存在的包
- 该 launch 从 `elfin10_ros2_gazebo` / `elfin10_ros2_moveit2` 取 URDF/SRDF，这两个包不在仓库中。**能用的是 `elfin5_ros2_moveit2/launch/elfin5_basic_api.launch.py`**（官方流程用的也是它）。

### 9. `use_sim_time` 声明了但没传
- `elfin5.launch.py:155-158` 声明 launch 参数 `use_sim_time`（默认 True），但未传入任何节点参数，节点实际用系统时钟。Gazebo 发 `/clock` 但没人听。当前未暴露问题，做录制回放/慢仿真时会踩坑。

## 环境/链路级（会导致仿真"看起来正常但机械臂不动"）

### 14. ~~断网网卡导致 FastRTPS 发现/数据通路瘫痪~~ ✅ 已修复（2026-08-20）
- **现象**：`ros2 node list` 超时或时有时无、`/clock`/`/rosout` 有发布者但收不到数据、节点间订阅偶发不通。Gazebo 物理正常（`gz topic -e /gazebo/default/world_stats` 在走），控制器 active，但 RViz/circle_motion 拿不到状态。
- **根因**：`enp2s0` 处于断网/EtherCAT 状态时，FastRTPS 默认在所有网卡上做 UDP 组播发现，该网卡上的发现/数据通路超时拖垮整个 DDS 图。
- **修复**：所有 ROS 进程以 `ROS_LOCALHOST_ONLY=1` 运行（DDS 只走回环）。已写入 `~/.bashrc`，并在 `start_sim.sh` / `start_sim.py` / `start_real.py` 内显式导出（gnome-terminal 以 `bash -c` 非交互运行，不读 `.bashrc`）。
- **注意**：设置后跨机 DDS 通信不可用；本仓库场景（单机 + EtherCAT 原始套接字）不受影响。

### 15. ~~move_group 没有 IK 插件，所有位姿规划 5 秒超时失败~~ ✅ 已修复（2026-08-20）
- **现象**：`ros2 launch elfin5_ros2_moveit2 elfin5.launch.py` 正常起来、控制器 active、直接发 `follow_joint_trajectory` 能动，但任何 MoveIt 规划（RViz / circle_motion）都在 5.2s 后报 `Plan and Execute request aborted`，move_group 日志为 OMPL `Unable to sample any valid states for goal tree`。
- **根因**：4 个 launch 文件都定义了 `robot_description_kinematics = {"robot_description_kinematics": kinematics_yaml}` 却**没有传给节点**，传的是裸 `kinematics_yaml`（变成顶层参数 `elfin_arm.kinematics_solver`，MoveIt 只认 `robot_description_kinematics.elfin_arm.*`）。
- **修复**：`elfin5.launch.py` / `elfin5_moveit.launch.py` / `elfin5_moveit_rviz.launch.py` / `elfin5_basic_api.launch.py` 的节点参数已改为 `robot_description_kinematics`。

### 16. `gazebo_ros_init` 的 `/clock` 只有发布者从不发数据（未修，影响低）
- `/clock` 有 publisher（QoS transient_local）但从未收到过样本，`/gazebo` 节点 `publish_rate=10`、`use_sim_time=True`。因 #9（节点全部用系统时钟）存在，当前不影响仿真与规划；做 bag 回放/时间敏感功能前需查 `gazebo_ros_init` 为何不发 `/clock`。
