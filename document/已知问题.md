- 需 PREEMPT_RT 内核 + `sudo chrt 10` 启动（`scripts/legacy/start_real.py:35-42`）。

## Launch 死代码（误导性，建议修）

### 6. `elfin5_gazebo.launch.py` 不加载控制器
- `elfin5_ros2_gazebo/launch/elfin5_gazebo.launch.py:87-95` 定义了两个 `ros2 control load_start_controller`，但**未加入 LaunchDescription**。单独启动它机械臂无法控制，且死代码里的控制器名 `joint_trajectory_controller` 与实际 `elfin_arm_controller` 不一致。

### 7. 真机两个 launch 各只启动一半
- `elfin5_moveit.launch.py`：构造了 move_group/RViz/spawner 但**只启动** static_tf + RSP + ros2_control_node。
- `elfin5_moveit_rviz.launch.py`：相反，**只启动** move_group + RViz + spawner，RSP/ros2_control_node 是死代码。
- 两者必须配对使用（官方 4 步流程就是这么干的），但单看任一文件都会误判。

### 8. `elfin_basic_api/launch/elfin_basic_api.launch.py` 引用不存在的包
- 该 launch 从 `elfin10_ros2_gazebo` / `elfin10_ros2_moveit2` 取 URDF/SRDF，这两个包不在仓库中。**能用的是 `elfin5_ros2_moveit2/launch/elfin5_basic_api.launch.py`**（官方流程用的也是它）。

### 9. `use_sim_time` 声明了但没传
- `elfin5.launch.py:155-158` 声明 launch 参数 `use_sim_time`（默认 True），但未传入任何节点参数，节点实际用系统时钟。Gazebo 发 `/clock` 但没人听。当前未暴露问题，做录制回放/慢仿真时会踩坑。

### 17. 驱动不校验从站数量：网口插错也能"正常运行"（2026-08-21 实踩）
- **现象**：enp2s0 插的是普通以太网（另一台电脑）而非机械臂时，驱动照常启动、服务照常返回 success，甚至打印"电压 48.5V"（实为陈旧缓冲区的固定垃圾值——两次启动分毫不差即为铁证）。姿态识别走 20s 超时后报 phase1 failed，且 `recognizePosition()` 不检查各从站结果，仍打印 `positions are recognized automatically`（误导）。
- **判真方法**：识别应几秒内无 WARN 通过；电压读数每次启动应有微小浮动；`/joint_states` 应与物理姿态一致。
- **操作铁律**：SOEM 只在驱动启动时扫环，换线后必须重启硬件驱动终端。

## 真机实测（2026-08-21，接真机验证记录）

### 18. DDS 跨用户 + 断网网卡：发现层窗口期瘫痪（已解决）
- **形态**：root 跑驱动、fit 跑 GUI/RViz/spawner。默认 DDS 下出现窗口期发现瘫痪：spawner 等 `/controller_manager` 10s 超时 exit 1（`controller_manager/spawner.py:45-61` 等的是 `get_node_names_and_namespaces()` 即纯参与者发现，不是服务本身）；GUI 收不到 `/tf_static`（报 "world does not exist"）；同用户（root↔root）调用正常，误导性强。
- **解决**：fit 与 root 双侧 `~/.bashrc` 统一 `export ROS_LOCALHOST_ONLY=1`（DDS 只走回环，把被 EtherCAT 裸占用的 enp2s0 踢出发现）；`fbb4c93` 在三个启动脚本内显式导出（gnome-terminal 以 `bash -c` 运行不读 bashrc；注意 `start_real.py` 驱动终端是 `sudo chrt 10 bash -c`，裸 sudo 清环境，只能靠脚本内导出）。
- **善后**：改环境变量必须重启全部 ROS 进程；全部停掉后可清理崩溃残留的 `/dev/shm/fastrtps_*` 与 `/dev/shm/sem.fastrtps_*`。
- **排查提示**：foxy 的 ros2 CLI 走 daemon 缓存，图查询诡异（如空 node list）先 `ros2 daemon stop && ros2 daemon start`，并用 `--no-daemon` 交叉验证，勿当真相。

### 19. 操作铁律：驱动终端重启后必须重跑 spawner
- 控制器存在 controller_manager **内存**里，驱动进程一没全没。重启 `elfin5_moveit.launch.py` 后必须补：
  `ros2 run controller_manager spawner.py joint_state_controller`
  `ros2 run controller_manager spawner.py elfin_arm_controller`
  否则无 `/joint_states` → RSP 停发 `/tf` 动态帧 → GUI/RViz 报 TF 错误（GUI 侧被 #20 的 catch-all 打印成同一句废话，无法区分）。
- 同理：换线后重启驱动（#17 的铁律）之后也要补 spawner。
- `start_real.py` 的依赖等待门控在 main 上因路径 bug 静默失效（`fbb4c93` 已修，修好后脚本会自动等依赖）。

### 20. GUI 轮询 IO 引发 slave5 SDO 报错 + catch-all 吞异常（已定位，未修）
- **链路**：`elfin_gui.py:921`（真机模式 0.2s 定时器 `monitor_DO_DI`）→ `/read_di` + `/read_do` 服务 → 驱动进程内 `elfin_ethercat_io_client.cpp:88` / `:95` **硬编码 slave 5 的 SDO 读**（`0x6001` DI / `0x7001` DO）→ 与 50Hz PDO 周期线程**无锁并发**，碰撞时 `elfin_ethercat_manager.cpp:362` 打印 `Failed to read from ... slave_no:5`。不起 GUI 就无此报错——slave5 报错是 GUI 轮询引发的，不是硬件掉线。
- **附带 bug**：`readSDO`（`manager.cpp:355-364`）读取失败时返回**未初始化**的栈垃圾 `val`。
- **吞异常**：`elfin_gui.py:887` 的 `except Exception` 把 TF 缺失 / 树不连通 / transforms3d 异常全部打印成同一句 `Get TF2 State Error...`。排查时临时改为 `'Get TF2 State Error: %r' % e`。
- **止血**：注释 `elfin_gui.py:921`（GUI 不再刷 DI/DO）或降频到 2.0s。**根治**：DI/DO 改走 PDO 映像，或 SDO 路径加互斥 + 重试 + 初始化 `val`。

### 21. `/joint_states` 关节顺序为 [J1,J2,J5,J3,J4,J6]（待真机核对）
- 驱动发布的 `name` 顺序实测为 `[elfin_joint1, elfin_joint2, elfin_joint5, elfin_joint3, elfin_joint4, elfin_joint6]`。TF/MoveIt 按名字匹配，不受影响。

- `count_zeros` 按 [J2,J1,J3,J4,J5,J6] 约定填充（见 #4），与该发布顺序的映射关系必须上电后逐关节比对数值确认。
