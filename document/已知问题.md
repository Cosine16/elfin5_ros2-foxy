### 17. 驱动不校验从站数量：网口插错也能"正常运行"（2026-08-21 实踩）

## 真机实测（2026-08-21，接真机验证记录）

### 18. DDS 跨用户 + 断网网卡：发现层窗口期瘫痪（已解决）
- **形态**：root 跑驱动、fit 跑 GUI/RViz/spawner。默认 DDS 下出现窗口期发现瘫痪：spawner 等 `/controller_manager` 10s 超时 exit 1（`controller_manager/spawner.py:45-61` 等的是 `get_node_names_and_namespaces()` 即纯参与者发现，不是服务本身）；GUI 收不到 `/tf_static`（报 "world does not exist"）；同用户（root↔root）调用正常，误导性强。
- **解决**：fit 与 root 双侧 `~/.bashrc` 统一 `export ROS_LOCALHOST_ONLY=1`（DDS 只走回环，把被 EtherCAT 裸占用的 enp2s0 踢出发现）；`fbb4c93` 在三个启动脚本内显式导出（gnome-terminal 以 `bash -c` 运行不读 bashrc；注意 `start_real.py` 驱动终端是 `sudo chrt 10 bash -c`，裸 sudo 清环境，只能靠脚本内导出）。
  - ⚠️ **2026-09-19 更正**：本条"解决"的归因**不完整**。真正让现场恢复的是**后来把 4 个终端都改成 sudo（统一 uid）**；`ROS_LOCALHOST_ONLY=1` 本身**不足以**让 root↔fit 互通，而且它还砍掉了唯一的回退通路（见 #22）。当时的"形态"（root 跑驱动 + fit 跑其余）**本身就是故障源**，不是需要靠环境变量绕过的外部条件。
- **善后**：改环境变量必须重启全部 ROS 进程；全部停掉后可清理崩溃残留的 `/dev/shm/fastrtps_*` 与 `/dev/shm/sem.fastrtps_*`。
- **排查提示**：foxy 的 ros2 CLI 走 daemon 缓存，图查询诡异（如空 node list）先 `ros2 daemon stop && ros2 daemon start`，并用 `--no-daemon` 交叉验证，勿当真相。**但先确认 uid 一致**（见 #22），否则重启 daemon 也没用。

### 19. 操作铁律：驱动终端重启后必须重跑 spawner

  `ros2 run controller_manager spawner.py joint_state_controller`
  `ros2 run controller_manager spawner.py elfin_arm_controller`
  否则无 `/joint_states` → RSP 停发 `/tf` 动态帧 → GUI/RViz 报 TF 错误（GUI 侧被 #20 的 catch-all 打印成同一句废话，无法区分）。
- 同理：换线后重启驱动（#17 的铁律）之后也要补 spawner。
- `start_real.py` 的依赖等待门控在 main 上因路径 bug 静默失效（`fbb4c93` 已修，修好后脚本会自动等依赖）。

### 20. GUI 轮询 IO 引发 slave5 SDO 报错 + catch-all 吞异常（已定位，未修）
- **链路**：`elfin_gui.py:921`（真机模式 0.2s 定时器 `monitor_DO_DI`）→ `/read_di` + `/read_do` 服务 → 驱动进程内 `elfin_ethercat_io_client.cpp:88` / `:95` **硬编码 slave 5 的 SDO 读**（`0x6001` DI / `0x7001` DO）→ 与 50Hz PDO 周期线程**无锁并发**，碰撞时 `elfin_ethercat_manager.cpp:362` 打印 `Failed to read from ... slave_no:5`。不起 GUI 就无此报错——slave5 报错是 GUI 轮询引发的，不是硬件掉线。
- **附带 bug**：`readSDO`（`manager.cpp:355-364`）读取失败时返回**未初始化**的栈垃圾 `val`。
- **吞异常**：`elfin_gui.py:887` 的 `except Exception` 把 TF 缺失 / 树不连通 / transforms3d 异常全部打印成同一句 `Get TF2 State Error...`。排查时临时改为 `'Get TF2 State Error: %r' % e`。
- **止血**：注释 `elfin_gui.py:921`（GUI 不再刷 DI/DO）或降频到 2.0s。**根治**：DI/DO 改走 PDO 映像，或 SDO 路径加互斥 + 重试 + 初始化 `val`。

### 22. ❗跨 uid 的 DDS 参与者互相发现不了 → 调试终端必须与节点同身份（2026-09-19 实测，硬约束）
- **形态**：实机节点以 root 运行（`start_real.py` 4 个终端全 sudo），普通用户在 fit 终端里
  `source scripts/elfin_env.sh` 后跑 `rqt` / `ros2 node list` —— **一片空白，一个节点都看不到**。
  而 `ps` 显示节点都在跑，`ss -lunp` 显示两侧都绑在 `127.0.0.1:7400` / `239.255.0.1:7400`。
- **根因**：**root 与 fit 的 DDS 参与者互不可见**，与 `ROS_LOCALHOST_ONLY`、umask、domain 是否干净**均无关**。
  机理：同机通信默认走 Fast-DDS 共享内存（SHM），**SHM 段跨 uid 打不开**；而
  `ROS_LOCALHOST_ONLY=1` 把组播限制在回环，本机 `lo` 网卡**没有 `MULTICAST` 标志**
  （`ip route get 239.255.0.1` → 走 `enx000ec68eca09`），于是**没有任何回退通路**。
- **实测矩阵**（两个自建 rclpy 节点互查，探针 `scripts/dds_discovery_probe.py`，均用干净 domain）：

  | 组合 | domain | `ROS_LOCALHOST_ONLY` | 其它条件 | 结果 |
  |---|---|---|---|---|
  | fit + fit | 42 / 45 | 1 / 0 | — | ✅ 互发现 |
  | **root + fit** | 42 / 44 / 46 | 1 / 0 | — | ❌ 各只看到自己 |
  | **root + fit** | 42 | 1 | root 侧 `umask 000`（段变 666） | ❌ |
  | **root + fit** | 43 | 1 | `lo` 开 MULTICAST + 组播路由指向 lo | ❌ |
  | fit + fit | **0** | 1 | domain 0 内有 root 参与者在跑 | ❌ |

- **已排除**（逐项验证，均非原因）：`/dev/shm` 容量（16G 用 2%）、残留 shm 段属主与权限、
  防火墙（iptables 全 ACCEPT / ufw 未启用）、端口绑定冲突、`ROS_LOCALHOST_ONLY` 与 `source`
  的先后顺序（ament 钩子 `1.ros_localhost_only.sh` 不会覆盖已设值）、domain 是否干净。
- **处置**：**实机上所有 ROS 进程必须同一 uid**。
  | 节点身份 | 调试终端 | 能否看到 | 做法 |
  |---|---|---|---|
  | root | root | ✅ | `bash scripts/root_ros.sh rqt`（实机现状用这个） |
  | fit | fit | ✅ | 目标形态：先提权再 `start_real.py --no-sudo`（见排查手册 §8） |
  | root + fit 混跑 | 任一侧 | ❌ | **禁止**：两组互不可见，spawner↔controller_manager 直接断链 |
- **连带修正**：
  - #18 的"解决"归因不完整 —— 真正生效的是统一 uid，`ROS_LOCALHOST_ONLY=1` 不是解药。
  - [[排查推测-面板与驱动通信调查]] 推测 3 的"❌ 证伪"判定**已被推翻**（本推测成立）；
    推测 4 的"环境/缓存/窗口"只是**次要**因素（会加剧误判，但修好也看不到跨 uid 节点）。
  - [[排查证据-面板与驱动通信调查]] 证据 5（跨用户 tf 到达）、证据 8（跨用户 service 成功）
    为**单次观测，未做 uid 对照**，结论存疑，以本次矩阵为准。
  - `start_real.py` 曾一度改成"驱动 root + 其余 fit"，该组合会让链路直接断掉，已回退为
    「全 sudo（默认）」+「全 fit（`--no-sudo`）」两种模式，不再提供混跑选项。
- **副作用提醒**：`sudo -E` 会让 root 把 `~/.ros`、`~/.rviz2` 写成一堆 root 所有的文件，
  之后普通用户的 `rqt` 会因"无法写入 `~/.ros/log`"直接报 `权限不够`（详见 `scripts/start_real.py`
  文件头的说明与已注入的 `ROS_HOME=/root/.ros` 隔离）。
